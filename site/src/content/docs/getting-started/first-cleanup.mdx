The interactive dashboard is the safest way to clean: you see every item before anything is removed, the recommended ones are preselected for you, and every deletion is re-checked at the last moment. This walkthrough follows one complete cleanup, screen by screen. The projects, paths and sizes are illustrative.

## Start the dashboard

```bash
lu-cleaner
```

`lu-cleaner clean` opens the same picker. Both need an interactive terminal (at least 40 × 10; 32 lines or more to see the details panel).

:::tip[Rehearse first]
Start with `lu-cleaner --dry-run`. Everything in this walkthrough works the same, the footer shows **○ dry-run**, and the final summary tells you what *would* have been freed. Nothing is touched.
:::

The usual filters pre-filter the dashboard, for example `lu-cleaner -c artifacts,worktrees --older-than 30d`. To start with nothing preselected, use `lu-cleaner clean --no-smart`.

| Element | Meaning |
| --- | --- |
| Header | Scan status, number of items listed, and the total that could be reclaimed. |
| 💾 line | Disk usage of the volume that holds your home folder, refreshed after each cleanup. |
| SIZE | What cleaning every item of the category would free. Report-only entries are not counted. |
| SELECTED | Size of the current selection in that category. |

The mode in the footer matters: **delete permanently** frees space immediately, **🗑 Trash mode** (toggled with `t`) moves files and folders to `~/.Trash`, frees nothing until you empty it and skips worktrees and commands (they cannot be undone), and **○ dry-run** touches nothing.

That bulk selection deliberately skips items of risk <span class="risk caution">caution</span>: you have to open the category and pick those one by one.

Each row is one item: something lu-cleaner can remove as a unit (a `node_modules` folder, a worktree, a cache, a simulator…).

| Column | Meaning |
| --- | --- |
| NAME | `project › path` for project artifacts; the `codex:` prefix means the project lives in a Codex worktree. |
| LOCATION | Where it is on disk. |

| AGE | Time since the item was last used. It turns yellow, with a `stale` tag, after 14 days (`stale_after`). |

Notice what smart select left out:

- `my-app › ios/build` was used 5 hours ago. Smart select never preselects the artifacts of a project used in the last 24 hours: you are probably working on it.
- `my-app › node_modules` and `my-app › ios/Pods` are <span class="risk moderate">moderate</span>: rebuilding them costs time, so they are only recommended once unused for 14 days.

Use `tab` / `shift+tab` to jump to the next or previous category, `←` to go back to the overview, `/` to filter by text and `s` to sort by size, age or name.

## 3. Select what to clean

| Key | Effect |
| --- | --- |
| `space` | Select or unselect the item under the cursor. |
| `a` | Smart select the current view: recommended items on, everything else off. |
| `A` | Select every cleanable item of the view, <span class="risk caution">caution</span> items included. |
| `n` | Select nothing in the view. |
| `i` | Invert the selection in the view. |

Inside a category, "the view" is the current list, after any `/` filter. On the category overview, it is every visible item. The selection is kept when you move between categories.

When you select a <span class="risk caution">caution</span> item, the status line tells you what is at stake, for example `⚠ caution: my-app · spike/old-ui — 3 uncommitted changes`.

Two kinds of items cannot be selected yet, and `space` tells you why:

- an item still being measured (`…` in SIZE): its checks are not finished, select it once its size is shown;
- an item that needs `--force`, such as an orphaned worktree folder whose uncommitted work git can no longer see. Start lu-cleaner with `--force` to delete it, or switch to Trash mode (`t`), which moves it to the Trash where you can still recover it.

## 4. Read the details

On a terminal of 32 lines or more, a details panel shows the item under the cursor (bottom of the screen above). `enter` toggles it: press it to show the panel on a smaller terminal, or to hide it on a large one.

| Line | What it tells you |
| --- | --- |
| First line | Name, risk, kind, scanner and number of files. |
| Path / Paths / Location | Exactly what will be removed. Group items (for example "Metro / Haste file maps (18)") list their first paths. |
| Method | `delete`, `trash (Trash mode)`, `command: …` (the tool's own cleanup, such as `xcrun simctl delete <UDID>`), `worktree` (`git worktree remove`) or `report`. In Trash mode, worktrees and commands show `skipped in Trash mode`. |
| Blocked / Force | Shown for an item that needs `--force`, with the reason. |
| Reclaim | Shown when part of the data is shared with other files (hardlinks or APFS clones) and deleting frees less than the size. |
| Age | Date of last use, and whether the item is stale. |
| Warning | Why an item is risky or was not recommended. |
| Note | What the item is and how it comes back if you need it again. |
| Project, Meta | The owning project and scanner details (branch, package manager, API level…). |

Press `o` to reveal the item in Finder.

<span class="acc">╰──────────────────────────────────────────────────────────────────────────╯</span>

- **Risk breakdown**: how many items of each risk, and their size. Items inside another selected item are cleaned with it and counted once.
- **Method**: delete permanently, move to Trash, or dry-run.
- **Skipped** (Trash mode only): worktrees and command items, which cannot be moved to the Trash and would delete permanently. Press `t` to switch back to delete mode if you want them.
- **Commands**: the external commands that will run, such as `xcrun simctl delete <UDID>` or `git worktree remove`.
- **Running**: some items refuse to be cleaned while an app uses them (Xcode for DerivedData, Simulator for simulators…). lu-cleaner checks those apps now; items guarded by a running app will be skipped, unless you started lu-cleaner with `--force`.
- **Largest**: the biggest items of the selection (on terminals of 24 lines or more).
- **Hidden**: selected items that the current `/` filter hides. They are cleaned too.

Press `y` or `enter` to confirm, `n` or `esc` to cancel. You can also clean before the scan is over: the dialog then warns that sizes may be partial.

Problems are listed first. Two numbers matter:

- **Estimated freed** adds up what each cleaned item was expected to free.
- **Measured freed** is the difference in free space on your home volume before and after the cleanup, as reported by the file system.

They are rarely identical, since other apps keep writing to disk. When the measured value is less than half the estimate, the summary suggests running `lu-cleaner doctor` (next section).

In Trash mode, what was moved to the Trash is never counted as freed: it gets its own line, **Moved to Trash … (not freed yet)**, and a reminder to empty the Trash.

Press any key to return to the lists. Cleaned items disappear; skipped and failed items stay listed and selected. To retry them, quit the app that blocked them and press `d` again.

Every cleanup is recorded in the history (`lu-cleaner history`), and when you quit with `q`, the summary of the last one is printed in your terminal:

## If the space is not freed

macOS does not always return deleted space right away. Here is what to check, in order:

<Steps>

1. **Run the doctor.** It lists APFS local snapshots, the size of the Trash and the running apps that block cleaning:

   ```bash
   lu-cleaner doctor
   ```

2. **Local snapshots** (Time Machine) keep the blocks of deleted files until they expire, after about 24 hours. `doctor` prints the `tmutil` commands to thin or delete them. lu-cleaner never runs them for you.

3. **The Trash.** If you cleaned in Trash mode (`t`, `--trash` or `use_trash = true`), nothing is freed until the Trash is emptied. The System category offers to empty it.

4. **Open files.** A running process keeps deleted files allocated until it exits: Simulator, Xcode, Gradle daemons (`./gradlew --stop`), Docker, an agent working in a worktree. Quit them.

5. **Other volumes.** The measured value only covers the volume of your home folder. Items cleaned on an external drive free space there instead.

</Steps>

[Why is my disk still full?](/lu-cleaner/guides/disk-space-not-freed/) covers each case in detail, including hardlinks, APFS clones, purgeable space and Docker's disk image.
