lu-cleaner est un binaire Go unique. Il n'installe ni daemon, ni agent de lancement, ni service en arrière-plan, et ne demande jamais `sudo`. Son [fichier de configuration](/lu-cleaner/fr/reference/configuration/) et son état privé sont créés selon les besoins. Les sauvegardes de mise à jour restent à côté de l'exécutable.

## Prérequis

| Prérequis | Détails |
| --- | --- |
| **macOS 12 Monterey ou plus récent** | Apple Silicon ou Intel. lu-cleaner ne fonctionne que sur macOS : il s'appuie sur APFS, `getattrlistbulk`, `xcrun simctl` et l'organisation de `~/Library` propre à macOS. |
| **Go 1.25 ou plus récent** | Nécessaire uniquement pour compiler et installer le binaire. |
| **git** | Utilisé par le scanner de worktrees (`git worktree list`, `git worktree remove`). Sans git, les worktrees ne sont tout simplement pas analysés. Les Command Line Tools de Xcode le fournissent. |

Tout le reste est facultatif : Xcode, Android Studio, Docker, les gestionnaires de versions de Node.js et les outils d'IA ne sont inspectés que s'ils sont installés.

## Installer avec `go install`

C'est la méthode recommandée :

```bash
go install github.com/ludwig-pro/lu-cleaner/cmd/lu-cleaner@latest
```

Go place le binaire dans `$(go env GOPATH)/bin`, en général `~/go/bin` (ou dans `$GOBIN` si vous l'avez défini). Si votre shell ne trouve pas `lu-cleaner` ensuite, ajoutez ce dossier à votre `PATH` :

```bash
echo 'export PATH="$PATH:$(go env GOPATH)/bin"' >> ~/.zshrc
source ~/.zshrc
```

Vérifiez l'installation :

```bash
lu-cleaner version
```

:::note
Un binaire compilé par `go install` affiche la version `dev`, car la chaîne de version est injectée à la compilation par le Makefile. Tout le reste fonctionne de la même façon.
:::

## Compiler depuis les sources

Utilisez cette méthode pour essayer une modification pas encore publiée ou pour contribuer.

<Steps>

1. Clonez le dépôt :

   ```bash
   git clone https://github.com/ludwig-pro/lu-cleaner.git
   cd lu-cleaner
   ```

2. Compilez `bin/lu-cleaner`. La version est tirée de `git describe` :

   ```bash
   make build
   ./bin/lu-cleaner scan --summary
   ```

3. Installez-le dans `$(go env GOPATH)/bin` :

   ```bash
   make install
   ```

</Steps>

`make run ARGS="scan --summary"` compile et lance en une seule étape, et `make test` exécute les tests unitaires. Consultez [Contribuer](/lu-cleaner/fr/about/contributing/) pour le processus de développement.

## Ajouter un alias court

`lu-cleaner` est long à taper. `make install` suggère `luc` :

```bash
echo 'alias luc=lu-cleaner' >> ~/.zshrc
source ~/.zshrc
luc scan --summary
```

Le reste de cette documentation écrit `lu-cleaner` en entier.

## Accorder l'accès complet au disque (facultatif)

La protection de la vie privée de macOS (TCC) empêche toute application de lire certains dossiers, sauf si vous lui accordez l'**accès complet au disque**. lu-cleaner fonctionne sans, mais quelques dossiers sont alors hors d'atteinte :

| Dossier | Sans accès complet au disque |
| --- | --- |
| `~/.Trash` | La Corbeille est listée sous le nom *Trash (size unknown — needs Full Disk Access)*. La nettoyer demande au Finder de la vider au lieu de supprimer directement les fichiers (le Finder peut vous demander une autorisation d'automatisation). `lu-cleaner doctor` indique que la taille de la Corbeille est inconnue. |
| `~/Library/Application Support/MobileSync/Backup` | Les sauvegardes d'iPhone et d'iPad faites par le Finder sont listées sous le nom *iPhone/iPad backups (size unknown)*. Elles sont de toute façon en rapport seul : lu-cleaner ne supprime jamais les sauvegardes d'appareils. |
| Conteneurs des autres applications : `~/Library/Containers/<app>`, `~/Library/Group Containers/<group>` | Jamais lus, mesurés ni nettoyés. Sur macOS 14 et versions ultérieures, y toucher ouvrirait une demande d'autorisation système qui bloquerait l'analyse jusqu'à ce que quelqu'un y réponde. Les entrées du catalogue qui y sont stockées (journaux de Docker Desktop, cache de Microsoft Teams, cache des illustrations d'Apple Music…) sont listées en rapport seul avec l'avertissement `needs Full Disk Access`, les images disque de Docker Desktop et d'OrbStack ne sont pas affichées, et `analyze` affiche ces dossiers sous la forme `🔒 app container — needs Full Disk Access`. |

`lu-cleaner analyze` vous avertit aussi lorsque certaines entrées sont illisibles et que leurs tailles sont partielles.

Pour l'accorder :

<Steps>

1. Ouvrez **Réglages Système → Confidentialité et sécurité → Accès complet au disque**.
2. Activez l'application depuis laquelle vous lancez lu-cleaner : Terminal, iTerm2, Ghostty, Warp, ou l'éditeur dont vous utilisez le terminal intégré. Ajoutez-la avec **+** si elle n'est pas dans la liste.
3. Quittez puis rouvrez cette application pour que l'autorisation s'applique.

</Steps>

:::tip
L'accès complet au disque est accordé à l'application de terminal, pas à lu-cleaner : toutes les commandes lancées depuis ce terminal en bénéficient. Ne l'accordez qu'à un terminal de confiance.
:::

## Mettre à jour

Le tableau de bord et les commandes interactives `clean`, `artifacts`, `worktrees`, `devices` et `analyze` recherchent une version stable plus récente sur GitHub au plus une fois par période de 24 heures. Cette vérification suit le consentement éventuel aux rapports techniques. La requête de recherche expire après 1,5 seconde. Un échec hors ligne compte comme la tentative du jour et votre commande continue normalement.

L'installation demande toujours une confirmation `[y/N]`. Entrée, non, une réponse invalide ou EOF refusent. `--yes` autorise seulement le nettoyage. Les rapports `scan` et `doctor`, `--list`, `--dry-run`, `--json`, les flux redirigés, la CI et l'exécution avec root désactivent la vérification. Pour la désactiver vous-même :

```bash
LU_NO_UPDATE=1 lu-cleaner
```

Exportez `LU_NO_UPDATE=1` dans votre configuration shell pour conserver ce choix. Toute valeur non vide désactive la vérification.

Les binaires issus d'une release et les installations `go install` d'une version stable publiée sont pris en charge lorsque le fichier et son dossier vous appartiennent, avec des permissions sûres. La confirmation précise qu'un binaire `go install` sera remplacé par la release GitHub précompilée. Les versions de développement inconnues, préversions, liens symboliques et chemins gérés par un gestionnaire de paquets sont ignorés. Vous pouvez continuer à utiliser votre méthode d'installation initiale.

L'outil télécharge uniquement l'archive officielle et son fichier `checksums.txt`, vérifie le SHA-256, puis valide l'exécutable macOS universel. Cette vérification garantit l'intégrité par rapport au compte publiant la release, pas une signature indépendante de l'éditeur. Les téléchargements sont limités à 60 secondes. Un échec avant le remplacement conserve l'exécutable et le nettoyage continue.

Avant le remplacement atomique, lu-cleaner crée une sauvegarde unique et vérifiée `.lu-cleaner-backup-*` dans le même dossier. Son chemin exact est affiché après le succès. La commande en cours conserve sa version d'origine. La suivante utilise la nouvelle version. Les sauvegardes ne sont jamais supprimées automatiquement. Si la synchronisation du dossier échoue après le remplacement, l'outil indique que la mise à jour est installée avec une durabilité incertaine et conserve la sauvegarde. Il ne restaure pas automatiquement par-dessus l'exécutable installé.

L'horodatage et les verrous entre processus se trouvent dans `$XDG_STATE_HOME/lu-cleaner/update`, ou `~/.local/state/lu-cleaner/update` par défaut. Ils ne contiennent ni cache de release, ni chemin d'exécutable, ni identifiant de connexion. Deux processus lu-cleaner coordonnent leurs vérifications et installations. D'autres programmes exécutés sous votre compte peuvent encore modifier votre exécutable entre sa dernière vérification et son remplacement.

Pour une mise à jour manuelle avec Go, relancez la commande d'installation :

```bash
go install github.com/ludwig-pro/lu-cleaner/cmd/lu-cleaner@latest
```

Depuis un clone, récupérez les changements et réinstallez :

```bash
git pull
make install
```

Votre configuration et votre historique sont conservés.

### Restaurer une sauvegarde

Fermez les autres commandes lu-cleaner. Remplacez les deux chemins ci-dessous par le chemin exact de sauvegarde affiché après la mise à jour et celui de l'exécutable indiqué dans la confirmation. Ces commandes copient la sauvegarde dans un fichier temporaire voisin, puis remplacent l'exécutable atomiquement. La sauvegarde est conservée.

```bash
backup="/chemin/exact/.lu-cleaner-backup-suffixe-affiche"
target="/chemin/exact/lu-cleaner"
staged="$(mktemp "${target}.restore.XXXXXX")"
cp "$backup" "$staged" && chmod 755 "$staged" && mv -f "$staged" "$target"
```

Exécutez `lu-cleaner version` pour vérifier la version restaurée. Gérez vous-même les sauvegardes lorsque vous n'en avez plus besoin.

## Désinstaller

Avant de supprimer le binaire, vérifiez où se trouvent vos fichiers. La configuration change d'emplacement si vous avez défini `LU_CLEANER_CONFIG` ou `XDG_CONFIG_HOME`, l'historique si vous avez défini `XDG_STATE_HOME` :

```bash
lu-cleaner config path    # le fichier de configuration
lu-cleaner config show    # affiche aussi le fichier d'historique
```

Supprimez ensuite le binaire, la configuration et l'historique :

```bash
rm "$(command -v lu-cleaner)"
rm -rf ~/.config/lu-cleaner        # config.toml, si vous en avez créé un
rm -rf ~/.local/state/lu-cleaner   # historique et état privé
```

Enfin, supprimez la ligne `alias luc=lu-cleaner` de `~/.zshrc` si vous l'avez ajoutée. Examinez séparément les sauvegardes `.lu-cleaner-backup-*` conservées à côté de l'exécutable.

:::caution
Si vous avez nettoyé avec `--trash` ou `use_trash = true`, les fichiers et dossiers qui y ont été déplacés sont toujours dans `~/.Trash`. Ils continuent d'occuper de l'espace disque tant que vous n'avez pas vidé la Corbeille.
:::
