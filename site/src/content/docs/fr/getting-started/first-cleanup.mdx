Le tableau de bord interactif est la façon la plus sûre de nettoyer : vous voyez chaque élément avant que quoi que ce soit ne soit supprimé, les éléments recommandés sont présélectionnés pour vous, et chaque suppression est revérifiée au dernier moment. Cette visite suit un nettoyage complet, écran par écran. Les projets, chemins et tailles sont donnés à titre d'illustration.

## Lancer le tableau de bord

```bash
lu-cleaner
```

`lu-cleaner clean` ouvre le même sélecteur. Les deux nécessitent un terminal interactif (au moins 40 × 10 ; 32 lignes ou plus pour voir le panneau de détails).

:::tip[Commencez par une répétition]
Lancez d'abord `lu-cleaner --dry-run`. Tout ce qui est décrit ici fonctionne de la même façon, le pied de page affiche **○ dry-run**, et le récapitulatif final indique ce qui *aurait* été libéré. Rien n'est touché.
:::

Les filtres habituels préfiltrent le tableau de bord, par exemple `lu-cleaner -c artifacts,worktrees --older-than 30d`. Pour démarrer sans aucune présélection, utilisez `lu-cleaner clean --no-smart`.

Cette sélection groupée ignore volontairement les éléments de risque <span class="risk caution">caution</span> : vous devez ouvrir la catégorie et les choisir un par un.

Les lignes grisées marquées `[·]` sont listées à titre informatif et ne peuvent pas être sélectionnées. Appuyez sur `space` sur l'une d'elles pour savoir pourquoi.

Remarquez ce que la sélection intelligente a laissé de côté :

- `my-app › ios/build` a été utilisé il y a 5 heures. La sélection intelligente ne présélectionne jamais les artefacts d'un projet utilisé au cours des dernières 24 heures : vous êtes probablement en train de travailler dessus.
- `my-app › node_modules` et `my-app › ios/Pods` sont <span class="risk moderate">moderate</span> : les reconstruire prend du temps, ils ne sont donc recommandés qu'après 14 jours sans utilisation.

Utilisez `tab` / `shift+tab` pour passer à la catégorie suivante ou précédente, `←` pour revenir à la vue d'ensemble, `/` pour filtrer par texte et `s` pour trier par taille, âge ou nom.

## 3. Sélectionner ce qu'il faut nettoyer

| Touche | Effet |
| --- | --- |
| `space` | Sélectionne ou désélectionne l'élément sous le curseur. |
| `a` | Sélection intelligente sur la vue actuelle : les éléments recommandés sont sélectionnés, tous les autres désélectionnés. |
| `A` | Sélectionne tous les éléments nettoyables de la vue, éléments <span class="risk caution">caution</span> compris. |
| `n` | Ne sélectionne rien dans la vue. |
| `i` | Inverse la sélection dans la vue. |

Dans une catégorie, « la vue » est la liste affichée, après un éventuel filtre `/`. Sur la vue d'ensemble des catégories, ce sont tous les éléments visibles. La sélection est conservée quand vous passez d'une catégorie à l'autre.

Quand vous sélectionnez un élément <span class="risk caution">caution</span>, la ligne d'état vous indique ce qui est en jeu, par exemple `⚠ caution: my-app · spike/old-ui — 3 uncommitted changes`.

## 4. Lire les détails

Sur un terminal de 32 lignes ou plus, un panneau de détails présente l'élément sous le curseur (en bas de l'écran ci-dessus). `enter` l'affiche ou le masque : appuyez dessus pour afficher le panneau sur un terminal plus petit, ou pour le masquer sur un grand.

| Ligne | Ce qu'elle vous apprend |
| --- | --- |
| Première ligne | Nom, risque, type, scanner et nombre de fichiers. |
| Path / Paths / Location | Exactement ce qui sera supprimé. Les éléments groupés (par exemple « Metro / Haste file maps (18) ») listent leurs premiers chemins. |
| Method | `delete`, `trash (Trash mode)`, `command: …` (le nettoyage propre à l'outil, comme `xcrun simctl delete unavailable`), `worktree` (`git worktree remove`) ou `report`. |
| Reclaim | Affichée quand une partie de la taille est partagée par des liens physiques (hardlinks) ailleurs et que la suppression libère moins. |
| Age | Date de dernière utilisation, et si l'élément est inactif (stale). |
| Warning | Pourquoi un élément est risqué ou n'a pas été recommandé. |
| Note | Ce qu'est l'élément et comment il revient si vous en avez de nouveau besoin. |
| Project, Meta | Le projet auquel il appartient et des détails fournis par le scanner (branche, gestionnaire de paquets, niveau d'API…). |

Appuyez sur `o` pour afficher l'élément dans le Finder.

- **Répartition par risque** : combien d'éléments de chaque niveau de risque, et leur taille.
- **Method** : suppression définitive, déplacement vers la Corbeille, ou simulation.
- **Commands** : les commandes externes qui seront lancées, comme `xcrun simctl delete unavailable` ou `git worktree remove`.

Appuyez sur `y` ou `enter` pour confirmer, sur `n` ou `esc` pour annuler. Vous pouvez aussi nettoyer avant la fin de l'analyse : la fenêtre signale alors que les tailles peuvent être partielles.

Tapez `yes` puis appuyez sur `enter`, ou sur `esc` pour annuler. Les éléments caution peuvent contenir quelque chose que vous ne pourrez pas régénérer : du travail non commité dans un worktree, des sessions d'agent, des données d'application. Une confirmation en une touche se déclenche facilement par réflexe ; taper un mot vous oblige à vous arrêter et à relire la liste.

La confirmation n'est pas la dernière vérification. Un worktree qui contient des modifications non commitées, qui est verrouillé ou qui porte des commits sur une HEAD détachée est encore refusé au moment de la suppression, sauf si vous avez lancé lu-cleaner avec `--force`. Voir [Modèle de sécurité](/lu-cleaner/fr/concepts/safety/).

| Marque | Signification |

- **Estimated freed** additionne ce que chaque élément nettoyé devait libérer.
- **Measured freed** est la différence d'espace libre sur le volume de votre dossier personnel entre avant et après le nettoyage, telle que la signale le système de fichiers.

Ils sont rarement identiques, puisque d'autres applications continuent d'écrire sur le disque. Quand la valeur mesurée est inférieure à la moitié de l'estimation, le récapitulatif suggère de lancer `lu-cleaner doctor` (section suivante).

Appuyez sur n'importe quelle touche pour revenir aux listes. Les éléments nettoyés disparaissent ; les éléments ignorés ou en échec restent listés et sélectionnés. Pour réessayer, quittez l'application qui les bloquait et appuyez de nouveau sur `d`.

Chaque nettoyage est enregistré dans l'historique (`lu-cleaner history`), et quand vous quittez avec `q`, le récapitulatif du dernier s'affiche dans votre terminal :

<div class="terminal">
<span class="ok">✓</span> 129 items cleaned · 65.4 GB freed (estimated)
&nbsp; Disk free: 43.0 GB → 108 GB (64.8 GB measured)
<span class="warn">Skipped:</span> 2
&nbsp; - codex:my-app › node_modules: in use: process 51234 runs a program or library from \~/.codex/worktrees/a1b2/my-app/node_modules
&nbsp; - shop-app: Xcode is running — quit it first (or use \-\-force)
</div>

## Si l'espace n'est pas libéré

macOS ne rend pas toujours l'espace supprimé immédiatement. Voici ce qu'il faut vérifier, dans l'ordre :

<Steps>

1. **Lancez le diagnostic.** `doctor` liste les instantanés locaux APFS, la taille de la Corbeille et les applications en cours d'exécution qui bloquent le nettoyage :

   ```bash
   lu-cleaner doctor
   ```

2. **Les instantanés locaux** (Time Machine) conservent les blocs des fichiers supprimés jusqu'à leur expiration, au bout d'environ 24 heures. `doctor` affiche les commandes `tmutil` pour les alléger ou les supprimer. lu-cleaner ne les lance jamais à votre place.

3. **La Corbeille.** Si vous avez nettoyé en mode Corbeille (`t`, `--trash` ou `use_trash = true`), rien n'est libéré tant que la Corbeille n'est pas vidée. La catégorie System propose de la vider.

4. **Les fichiers ouverts.** Un processus en cours d'exécution garde les fichiers supprimés alloués jusqu'à ce qu'il se termine : Simulator, Xcode, les daemons Gradle (`./gradlew --stop`), Docker, un agent qui travaille dans un worktree. Quittez-les.

5. **Les autres volumes.** La valeur mesurée ne concerne que le volume de votre dossier personnel. Les éléments nettoyés sur un disque externe libèrent de l'espace sur ce disque-là.

</Steps>

[Pourquoi l'espace libéré n'apparaît pas](/lu-cleaner/fr/guides/disk-space-not-freed/) détaille chaque cas, y compris les liens physiques, les clones APFS, l'espace purgeable et l'image disque de Docker.
