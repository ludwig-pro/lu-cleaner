## Pourquoi un nouveau nettoyeur ?

Les agents de code IA ont changé ce qui remplit le disque d'un développeur. Chaque tâche Codex, Cursor, Conductor ou Claude Code peut créer une **worktree git** avec ses propres `node_modules`, `ios/Pods` et builds Android. Les simulateurs accumulent en silence des gigaoctets d'enregistrements de tests UI. Les gestionnaires de paquets gardent plusieurs caches globaux et versions de Node. Les nettoyeurs généralistes ne connaissent pas ces emplacements, ou les évitent volontairement.

lu-cleaner les connaît — et sait lesquels peuvent être supprimés sans risque.

<CardGrid>
	<Card title="Worktrees d'agents IA" icon="seti:git">
		Trouve chaque worktree liée (Codex, Cursor, Conductor, Claude Code, manuelle), affiche sa branche et son état — propre, modifiée, non poussée, mergée, orpheline — et retire celles qui sont terminées avec `git worktree remove`. Les branches sont toujours conservées.
	</Card>
	<Card title="Pensé pour React Native" icon="seti:react">
		Analyse façon npkill des `node_modules`, `ios/Pods`, `ios/build`, `android/app/build`, `.gradle`, `.cxx`, `.expo`… avec vérification des fichiers marqueurs et du `.gitignore` : un dossier `build` qui contient du code source n'est jamais touché.
	</Card>
	<Card title="Simulateurs et émulateurs" icon="laptop">
		Simulateurs iOS, runtimes, dossiers d'appareils orphelins, enregistrements XCTest et logs unifiés ; AVD Android, images système inutilisées, NDK et distributions Gradle — y compris les SDK sur disque externe.
	</Card>
	<Card title="Sûr par conception" icon="approve-check">
		Chaque chemin est revérifié juste avant la suppression : identifiants et configurations protégés, identité d'inode, applications ouvertes, bases de données ouvertes, processus qui travaillent dedans, travail non commité. Dry-run partout.
	</Card>
	<Card title="Rapide" icon="rocket">
		Écrit en Go. Utilise l'appel macOS `getattrlistbulk` pour lire un dossier entier en un seul appel système — environ 3× plus rapide que `du` — et affiche les résultats au fil de l'eau.
	</Card>
	<Card title="Scriptable et compatible LLM" icon="document">

## Essayez en 30 secondes

<Tabs>
	<TabItem label="Interactif">
		```bash
		go install github.com/ludwig-pro/lu-cleaner/cmd/lu-cleaner@latest
		lu-cleaner            # tableau de bord, éléments recommandés présélectionnés
		```
	</TabItem>
	<TabItem label="Tout choisir soi-même">
		```bash
		lu-cleaner clean --no-smart   # rien n'est présélectionné
		lu-cleaner worktrees          # uniquement les worktrees git
		lu-cleaner artifacts          # uniquement node_modules, Pods, builds…
		```
	</TabItem>
	<TabItem label="Scripts">
		```bash
		lu-cleaner scan --json > report.json
		lu-cleaner clean --yes --smart --dry-run   # le plan, rien n'est supprimé
		lu-cleaner clean --yes --smart             # nettoie les éléments recommandés
		```
	</TabItem>
</Tabs>
