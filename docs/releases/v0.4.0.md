# v0.4.0 — Technical diagnostics and racing documentation

lu-cleaner can now report internal errors and recovered Go panics to the maintainer's dedicated Sentry project, **only after explicit consent**. Reporting is off by default, and refusing it leaves every feature available.

- New `diagnostics status`, `enable`, `disable` and `export` commands. Consent is separate from cleanup confirmation, tied to the recipient and notice version, and can be revoked.
- Reports contain fixed technical codes, release/OS/architecture, command, scan mode and relative lu-cleaner source frames. They exclude personal paths, file contents, arguments, environment, raw errors/logs and permanent user or device identifiers.
- Official release binaries contain the public Sentry DSN. The project stores error events in the EU, with IP and derived location scrubbing verified on a synthetic event. Reports use bounded, best-effort delivery without retries or a disk upload backlog.
- Worker panics now propagate explicit failures, stop further cleanup admissions and wake shared size/cache consumers. Incomplete scans are not reused as valid sizes.
- Local history and diagnostic state use private permissions, refuse unsafe files and bound storage. History write failures produce warnings separately from cleanup results.
- The EN/FR documentation now uses a light white/red racing theme, with a finer pixel flag, a pause control, reduced-motion support and animation suspension when hidden or out of view.
- CI checks the race detector across the workers, private state and consent packages.

## Installation and consent

Download the universal macOS binary and `checksums.txt` from this release. Apple Silicon and Intel are included; macOS 12 or later is required.

```sh
lu-cleaner --version
lu-cleaner diagnostics status
lu-cleaner diagnostics enable   # read the notice, then choose explicitly
lu-cleaner diagnostics disable
```

Source installation remains available:

```sh
go install github.com/ludwig-pro/lu-cleaner/cmd/lu-cleaner@v0.4.0
```

Source builds need a public `LU_DIAGNOSTICS_DSN` at runtime or build time to enable remote reporting. No Sentry administration token is required. See the [technical reports and privacy guide](https://ludwig-pro.github.io/lu-cleaner/guides/diagnostics/) and [French documentation](https://ludwig-pro.github.io/lu-cleaner/fr/).

## Validation and limits

Local Go tests, vet, the targeted race detector, cgo and no-cgo builds, both universal architectures, generated documentation and the Astro site build passed. A synthetic report was received and its stored JSON verified in Sentry. No full scan or deletion of the real home folder was used as a release test.

Reporting covers recovered Go panics and selected internal failures. SIGKILL, hard reboot, native crashes and some runtime fatal errors can prevent delivery. The receiver necessarily sees the IP of the HTTPS connection even when it is scrubbed from events. The free Developer plan supplies 30 days of detailed event history; aggregated metadata can remain longer. Nothing is presented as anonymous or as coverage of every crash type.
